# UI Quality Gate

CopyPaste 是面向真实用户发布的产品，UI 改动不能只以“功能可用”作为完成标准。任何涉及界面、交互、布局、主题、文案或发布截图的改动，都必须通过本规约。

## 本次问题复盘

- 现代设置页只完成了功能切换，没有按产品界面做完整视觉验收。
- 子导航使用英文文案，与中文产品语境不一致。
- 选中状态不明显，缺少当前页面的视觉反馈。
- 设置窗口尺寸过大，内容密度过低，造成空旷和失衡。
- 经典/现代设置页没有共用表单布局规则，标签、控件和操作按钮对齐混乱。
- 现代设置页左侧导航没有形成稳定左对齐视觉轴，右侧内容也被标签列推到页面中部，整体像“漂浮的一小团控件”。
- 浅色模式下使用半透明灰色 surface，且父级背景没有稳定色值，导致窗口整体发灰。
- 经典主面板允许纵向拉伸，但经典横向卡片布局没有消费额外高度，导致底部出现大面积无意义空白。
- 修复经典主面板高度时使用了窗口级 `maxSize`，虽然本意只限制高度，但实际 resize 体验会让宽度调整也变得不自然。
- 验收依赖编译通过和功能可用，没有做真实界面截图、主题切换和状态矩阵检查。

## 根因

- 没有先定义 UI 质量标准和验收矩阵，就直接进入实现。
- 使用了临时视觉参数，例如半透明背景和随手尺寸，而不是明确的设计 token。
- 对 AppKit layer 背景色的动态外观刷新考虑不足。
- 没有把中文文案、选中态、浅色/深色、窗口尺寸、长文本、空状态等视为必须验收项。
- 没有在动手前明确页面的视觉锚点：导航区从哪里开始对齐，内容区从哪里开始阅读，选中态占据整行还是只包住文字。
- 没有把可调整窗口的最小、默认、最大、用户手动拉伸尺寸纳入技术方案和验收矩阵。
- 对 resize 的修复没有区分轴向，错误地用窗口整体限制解决单轴布局问题。
- 没有在提交前进行真实运行截图检查；构建通过被误当成完成。

## 强制质量门禁

每次 UI 改动提交前必须检查：

1. 产品语境
   - 文案语言与当前产品一致；CopyPaste 当前默认中文 UI 不应混入英文导航。
   - 标题、按钮、tab、菜单、状态提示语义清晰，不使用占位文案。

2. 布局
   - 表单类页面必须使用固定标签列和控件列，标签右对齐，控件左对齐。
   - 设置/管理类界面必须先定义视觉轴：侧边导航左边缘、内容标题左边缘、表单控件左边缘必须有可解释的一致关系。
   - 侧边导航项必须使用完整行宽点击区域；图标与文字左对齐，不允许只做包住文字的小胶囊导致视觉漂移。
   - 如果一个设置分组只有少量选项，优先使用顶部标题 + 左对齐选项组；不要为了套“表单标签列”把复选框推到内容卡片中间。
   - 同一页面内边距、行距、分组标题、按钮尺寸必须一致。
   - 窗口尺寸要服务内容密度；内容多时滚动，内容少时不拉大窗口。
   - 可调整窗口必须定义最小、默认、最大尺寸；如果布局无法消费额外空间，就不要允许产生无意义拉伸。
   - 限制可调整窗口时必须区分横向和纵向；不要用会牵连另一轴的全局尺寸锁解决单轴问题。
   - 不允许 UI 元素重叠、截断、漂移或出现无意义大空白。

3. 视觉状态
   - 当前 tab、当前筛选、选中项必须有明确高亮。
   - hover、selected、disabled、empty、error、permission-missing 等状态应可识别。
   - 图标与文字按钮要符合平台习惯，按钮功能要能从视觉上判断。

4. 主题与颜色
   - 浅色和深色模式都必须检查。
   - 设置、表单、管理类界面优先使用不透明 surface；不要用半透明灰色承载主要内容。
   - layer 背景色不能只在创建时设置；外观切换后必须刷新。
   - 文本和背景要有足够对比度，不能出现灰蒙蒙、脏色、低可读性。

5. 内容弹性
   - 检查长文本、空数据、多数据、窄窗口、最小窗口尺寸。
   - 检查可调整窗口的默认尺寸、最大尺寸和用户手动拉伸后的布局。
   - 固定格式控件要有稳定宽高，不能因为内容变化导致布局跳动。

6. 真实验收
   - 不能用生成的 mockup 代替真实 App 截图。
   - 至少验证经典/现代、浅色/深色、主要 tab 或主要流程。
   - 如果系统权限导致无法截图，必须在交付说明中明确说明未完成的视觉验收风险。

## 参考基准

- Apple Human Interface Guidelines: Color
  - https://developer.apple.com/design/human-interface-guidelines/color
  - 使用能适配不同背景、外观模式和可访问性设置的系统/语义颜色；不要随手写临时颜色。
- Apple Human Interface Guidelines: Dark Mode
  - https://developer.apple.com/design/human-interface-guidelines/dark-mode
  - 深色模式不是简单反色；需要为背景、层级、文本和控件状态分别验证。
- W3C WCAG Contrast Minimum
  - https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html
  - 普通文本对比度目标至少 4.5:1，大号文本至少 3:1。
- Apple Human Interface Guidelines: Layout
  - https://developer.apple.com/design/human-interface-guidelines/layout
  - 窗口和布局需要在不同尺寸下保持内容关系清晰，不能只验证默认尺寸。
- Nielsen Norman Group: Group Form Elements Effectively Using White Space
  - https://www.nngroup.com/articles/form-design-white-space/
  - 标签要靠近对应控件，相似项要通过空白和分组建立关系。
- Nielsen Norman Group: Why Does a Design Look Good?
  - https://www.nngroup.com/articles/why-does-design-look-good/
  - 一致的左对齐、排版系统和间距能让界面更容易阅读，也更有整体感。

## CopyPaste 设置页专项约束

- 现代设置导航必须使用中文：通用、快捷键、外观、忽略应用。
- 现代设置导航必须整行左对齐，选中状态必须覆盖完整导航行，而不是只包住图标和文字。
- 现代设置选中导航必须有背景高亮和强调色文字，未选中项也要保持同一左边缘。
- 现代设置内容区标题、说明和控件组应左对齐；少量复选框不使用右对齐标签列。
- 现代设置窗口默认尺寸保持紧凑，当前基准为 `740 x 520`，最小尺寸不低于 `700 x 480`。
- 经典设置窗口默认尺寸保持可读，当前基准为 `640 x 680`，内容通过滚动承载。
- 设置页基础字号不低于 14；辅助说明不低于 12。
- 设置页 surface 使用明确浅/深色，不用半透明灰作为主要背景。
- 透明度设置只影响剪贴板主面板，不应让设置窗口变成半透明灰。
- 经典主面板是横向卡片布局，不能允许纵向拉出大面积空白；当前最高高度基准为 `520`。
- 经典主面板仍必须允许横向调整；高度限制应通过 resize delegate 只夹住高度，不能锁住宽度体验。

## Definition of Done

UI 任务只有同时满足以下条件才算完成：

- 功能行为正确。
- 视觉布局在真实 App 中可接受。
- 浅色和深色模式可读。
- 主要状态有明确反馈。
- 构建和发布产物校验通过。
- 本文件的强制质量门禁已逐项检查。
